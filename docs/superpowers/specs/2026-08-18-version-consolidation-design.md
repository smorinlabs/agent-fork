# agent-fork — Version String Consolidation: Design Options

**Date:** 2026-08-18 · **Status:** draft, two Fable rounds (round 1: adversarial review of options A-D; round 2: co-design of Option E, including primary-source verification of release-please's `extra-files` mechanism), pending owner decision.
**Method:** Direct repo search across all file types, cross-checked against a real version bump that landed mid-analysis (PR #47, `1.0.0` → `1.1.0`, which missed most of the sites this doc is about). Verified against live repo state, git history, an empirical `uv lock`/`uv version` test, and primary-source reading of `googleapis/release-please`'s updater code. No implementation until the owner picks an option.

## 1. Problem

`agent-fork`'s own release version (currently `1.1.0`, source of truth `pyproject.toml:3`) is duplicated as a hardcoded literal string in **9 places across 7 files**. Bumping the version requires editing all of them by hand; nothing enforces that they agree.

| Category | Files | Count |
|---|---|---|
| Source of truth | `pyproject.toml:3` | 1 |
| Auto-regenerated by `uv lock`/`uv version` — confirmed empirically | `uv.lock:7` | 1 |
| Runtime-dynamic, reads `pyproject.toml`'s built metadata via `importlib.metadata.version("agent-fork")`, never manually edited | `src/agent_fork/__init__.py:5`, `src/agent_fork/cli.py:57` | 2 |
| **Hardcoded literals — the actual problem** | `src/agent_fork/codex_app_server.py:122`, `tests/cli/test_cli.py:43`, `scripts/check_clean_install.sh:12`, `.claude-plugin/plugin.json:3`, `.claude-plugin/marketplace.json:9` and `:16`, `.codex-plugin/plugin.json:3`, `README.md:147` and `:190` | **9** |

**Evidence this is a real, not theoretical, risk:** PR #47 bumped the version from `1.0.0` to `1.1.0`. Of the 9 hardcoded literal sites, it updated **2** (`tests/cli/test_cli.py`, `scripts/check_clean_install.sh`) and **missed 7, across 5 files** — including `README.md`, which the PR *did edit* (29 lines changed) without touching either of its two stale version mentions. The failure mode isn't "forgot to open the file" — it's "edited the file, still missed the version string in it."

Current stale state (still `1.0.0` after the merge): `src/agent_fork/codex_app_server.py:122`, `.claude-plugin/plugin.json:3`, `.claude-plugin/marketplace.json:9` and `:16`, `.codex-plugin/plugin.json:3`, `README.md:147` and `:190`.

**Why the 9 hardcoded sites split into three different problems, not one:**

- **A real bug in source code** (`codex_app_server.py:122`): this is a JSON-RPC handshake to the Codex app-server, sent by running Python code. It should follow the same pattern `__init__.py`/`cli.py` already use — `importlib.metadata.version("agent-fork")` — but doesn't, and never has.
- **Intentional tripwires** (`tests/cli/test_cli.py`, `scripts/check_clean_install.sh`): both run in CI (the `matrix-and-tests` and `conformance` jobs) and assert the *expected* version string as a smoke test that a release actually shipped the version it claims to.
- **Independent-but-currently-coupled manifests** (`.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` ×2, `.codex-plugin/plugin.json`, `README.md` ×2): JSON/Markdown files with no Python runtime, so they can't call `importlib.metadata`. `.claude-plugin/plugin.json:3` and `.codex-plugin/plugin.json:3` are the **plugin's** version; `.claude-plugin/marketplace.json:16` is the same plugin's version restated inside the marketplace listing; `.claude-plugin/marketplace.json:9` is the **marketplace listing's own** version (`metadata.version`), a third, conceptually distinct object.

## 3. Options considered

### 3.1 Option A — Fix the one real bug, document the rest

Fix `codex_app_server.py`, repair the 7 stale literals by hand, add a manual checklist. **Superseded** — see §4.

### 3.2 Option B — Automated bump script (no forward-compat design)

A + a hand-rolled idempotent-per-site rewrite script, with no attempt to match release-please's own addressing conventions. **Superseded** — see §4.

### 3.3 Option C — Bump script plus a drift-detection CI test

B + a test asserting all 9 sites match `pyproject.toml`. **Superseded** — see §4.

### 3.4 Option D — Drift test now, defer all automation to release-please (P01-T20)

Fix `codex_app_server.py`, repair the stale sites once, ship only the drift test; version bumps stay manual until T20 lands. **Rejected by the owner:** *"I would like something more comprehensive. Hand-updating is not what I'm looking for, and we have it in too many places. How can we have this all from one root location that eventually will be managed by release-please."* Superseded by Option E below.

### 3.5 Option E — Fully automated single-source propagation, release-please-shaped (recommended)

**Design goal:** no version site is ever hand-edited for a normal bump, starting now — not "once T20 lands." The interim mechanism is built to use release-please's own addressing conventions, verified from its source (§3.5.6), so that when P01-T20 is implemented, adopting it means adding one config file and deleting one script — no target file gets reformatted a second time.

#### 3.5.1 What release-please's `extra-files` mechanism actually does (verified, not assumed)

Read directly from `googleapis/release-please@main` source (citations in §3.5.6):

- **JSON/YAML/TOML/XML files** are addressed by explicit **jsonpath/xpath**, e.g. `{"type": "json", "path": "...", "jsonpath": "$.metadata.version"}`. There is no marker convention for these formats — they can't carry comments, so jsonpath is the only mechanism release-please offers. **A plain-string `.json` entry defaults to jsonpath `$.version`**, which would silently do nothing on a file like `marketplace.json` that has no root-level `version` field — release-please does not error on an unmatched jsonpath, it silently no-ops. This is a real footgun the design below avoids by always using explicit jsonpath entries.
- **Files with no recognized structured extension** (`.md`, `.py`, `.sh`) get the **`generic` updater**: it scans for the literal token `x-release-please-version` (also `-major`/`-minor`/`-patch` variants) appearing anywhere on a line — no required comment syntax — and replaces any semver-shaped substring on that line with the new version, regardless of what version is currently there. This is the marker convention text files need.
- **`pyproject.toml` needs no `extra-files` entry** — release-please's `python` release-type bumps it natively.

#### 3.5.3 New file: `scripts/sync_versions.py`

Stdlib-only (Python 3.11+ `tomllib`, no new dependency). Reads `pyproject.toml`'s version and rewrites every declared site idempotently — deliberately **stricter** than release-please: a missing jsonpath, a missing/extra annotation, or an annotated line with no semver is a **hard error**, where release-please would silently no-op. A lost marker must fail loudly here, since this script (unlike release-please) is the only thing enforcing propagation until T20.

```python
#!/usr/bin/env python3
"""Propagate pyproject.toml's version to every declared site.

Interim stand-in for release-please extra-files (P01-T20). Addressing
conventions are release-please's own, so migration = add
release-please-config.json mirroring the tables below, delete this script.
  - JSON sites: jsonpath addressing (release-please `json` updater).
  - Text sites: `x-release-please-version` inline annotations
    (release-please `generic` updater) -- any semver on an annotated
    line is rewritten, regardless of its current value.
Deliberately stricter than release-please: a missing jsonpath, a missing
annotation, or an annotated line with no semver is a hard error here
(release-please silently skips) -- lost markers must fail loudly.
"""
import argparse, json, re, sys, tomllib
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent
SEMVER = re.compile(r"\d+\.\d+\.\d+(?:-[\w.]+)?(?:\+[-\w.]+)?")  # release-please's pattern
ANNOTATION = "x-release-please-version"

# Mirror of the future release-please-config.json `extra-files` entries.
JSON_SITES = {                       # path -> list of dotted paths ($.-less jsonpath)
    ".claude-plugin/plugin.json": ["version"],
    ".codex-plugin/plugin.json": ["version"],
    ".claude-plugin/marketplace.json": ["metadata.version", "plugins.0.version"],
}
GENERIC_SITES = {                    # path -> expected annotation count
    "tests/cli/test_cli.py": 1,
    "scripts/check_clean_install.sh": 1,
    "README.md": 1,
}

def _set(obj, dotted, value):
    *parents, leaf = dotted.split(".")
    for key in parents:
        obj = obj[int(key)] if isinstance(obj, list) else obj[key]
    if leaf not in obj:
        raise KeyError(dotted)
    obj[leaf] = value

def render_json(path, dotted_paths, version):
    raw = path.read_text()
    data = json.loads(raw)
    canonical = json.dumps(data, indent=2, ensure_ascii=False) + "\n"
    if canonical != raw:                       # round-trip guard: never silently reformat
        sys.exit(f"{path}: not in canonical 2-space JSON form; refusing to rewrite")
    for dotted in dotted_paths:
        _set(data, dotted, version)
    return json.dumps(data, indent=2, ensure_ascii=False) + "\n"

def render_generic(path, expected_count, version):
    lines, hits = path.read_text().splitlines(keepends=True), 0
    for i, line in enumerate(lines):
        if ANNOTATION in line:
            if not SEMVER.search(line):
                sys.exit(f"{path}: annotated line {i + 1} has no semver to replace")
            lines[i] = SEMVER.sub(version, line)
            hits += 1
    if hits != expected_count:                 # a deleted marker shrinks coverage loudly
        sys.exit(f"{path}: expected {expected_count} '{ANNOTATION}' line(s), found {hits}")
    return "".join(lines)

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--check", action="store_true",
                         help="exit 1 on drift instead of writing")
    args = parser.parse_args()
    version = tomllib.loads((ROOT / "pyproject.toml").read_text())["project"]["version"]
    drift = []
    for rel, spec in list(JSON_SITES.items()) + list(GENERIC_SITES.items()):
        path = ROOT / rel
        desired = (render_json(path, spec, version) if rel in JSON_SITES
                   else render_generic(path, spec, version))
        if desired != path.read_text():
            drift.append(rel)
            if not args.check:
                path.write_text(desired)
                print(f"synced {rel}")
    if args.check and drift:
        sys.exit("version drift vs pyproject.toml (run `just bump` or "
                  "`uv run python scripts/sync_versions.py`): " + ", ".join(drift))

if __name__ == "__main__":
    main()
```

#### 3.5.4 `justfile` wiring

Verified: CI's `matrix-and-tests` job runs `just all`, so this covers CI with **zero workflow-file changes**.

```make
# Bump the version everywhere: part = major | minor | patch | an explicit X.Y.Z
bump part:
    #!/usr/bin/env bash
    set -euo pipefail
    case "{{part}}" in
      major|minor|patch) uv version --bump "{{part}}" ;;
      *)                 uv version "{{part}}" ;;
    esac
    uv run python scripts/sync_versions.py
    git diff --stat

# Verify every version site matches pyproject.toml
version-check:
    uv run python scripts/sync_versions.py --check

all: fmt lint typecheck version-check test
```

`uv version` (confirmed available, `uv 0.11.29`) supports `uv version [VALUE]` and `--bump major|minor|patch`, and re-locks `uv.lock` itself by default (`--frozen` opts out) — no separate `uv lock` step needed.

**How a human bumps the version, end to end — this replaces every manual edit:**

```bash
just bump minor        # or: just bump 1.2.0
# -> uv rewrites pyproject.toml + uv.lock; sync_versions.py rewrites the 5 files;
#    git diff --stat shows exactly what changed
git checkout -b chore/bump-1.2.0
git commit -am "chore: bump version to 1.2.0"   # then PR as usual
```

No site is ever hand-edited. If someone edits `pyproject.toml` directly and skips the script, `just all` — locally and in CI — fails at `version-check` and names the stale files.

**Generated output is committed, not gitignored.** The plugin/marketplace manifests are read from the repo by Claude Code's/Codex's marketplace machinery, and `README.md` renders on GitHub — none of these can be build-time-only artifacts. `--check` is what makes committed-and-generated safe. No pre-commit hook is added: the repo has no `.pre-commit-config.yaml` today, and `just all` (which every PR already runs) is one consistent gate rather than two with different failure UX.

**The first run doubles as the drift repair.** Because every rewrite is per-site idempotent (any semver on an annotated line / at a jsonpath → current version, regardless of what was there), running `uv run python scripts/sync_versions.py` once converges the 7 currently-stale sites from today's mixed `1.0.0`/`1.1.0` state to `1.1.0` in a single pass.

#### 3.5.5 Decision on the two CI tripwires

**Keep both as literal assertions — annotated and machine-written, not converted to dynamic reads.**

```python
assert completed.stdout == b"agent-fork 1.1.0\n"  # x-release-please-version
```
```bash
test "$version_output" = "agent-fork 1.1.0" # x-release-please-version
```

A dynamic read (e.g. `importlib.metadata` inside the test itself) would make the assertion compare the built artifact to itself, proving nothing about packaging. Keeping the literal — but machine-writing it — preserves the real check ("does the built/installed artifact report the version the repo's committed state claims") while removing all hand-editing. Their role shifts: pre-automation they caught "did the human remember to bump this"; post-automation (and post-T20) they catch a stale build/venv, broken metadata plumbing, or — once release-please is live — a misconfigured `extra-files` entry that silently no-op'd. `version-check` is the drift tripwire; these two are build-integrity tripwires. Both are now fully machine-written.

#### 3.5.6 Migration to real release-please (P01-T20)

When T20 lands, `release-please-config.json` gets an `extra-files` block that is a direct transcription of §3.5.2/§3.5.3's tables:

```json
{
  "packages": {
    ".": {
      "release-type": "python",
      "extra-files": [
        { "type": "json", "path": ".claude-plugin/plugin.json",      "jsonpath": "$.version" },
        { "type": "json", "path": ".codex-plugin/plugin.json",       "jsonpath": "$.version" },
        { "type": "json", "path": ".claude-plugin/marketplace.json", "jsonpath": "$.metadata.version" },
        { "type": "json", "path": ".claude-plugin/marketplace.json", "jsonpath": "$.plugins[0].version" },
        "tests/cli/test_cli.py",
        "scripts/check_clean_install.sh",
        "README.md"
      ]
    }
  }
}
```

All JSON entries stay explicit objects (never plain strings — see §3.5.1's footgun). The three text files are plain strings on purpose: no recognized extension routes them to the `generic` updater, which finds the annotations already sitting in those files. Migration steps: add that config plus `.release-please-manifest.json`, wire the workflow per the org pattern, **delete `scripts/sync_versions.py` and the `bump` recipe**, and **keep `version-check`** — it now doubles as a live correctness check on release-please's `extra-files` config (a misconfigured jsonpath silently no-ops in release-please; `version-check` catches it on the release PR itself, before merge). Not one of the 7 target files is touched again during migration — only the addressing conventions already baked into them get reused by a different actor.

#### 3.5.7 Risks and edges

- **Silent no-op vs. loud failure.** release-please's default failure mode for a misaddressed site is silence; the interim script's is a hard error (missing jsonpath, wrong annotation count, no semver on an annotated line). This is deliberate and is exactly why `version-check` should outlive the script into the release-please era.
- **JSON reformatting.** The script refuses to touch a JSON file that isn't already in canonical 2-space form (round-trip guard) rather than silently reformatting it whole.
- **README prose is a sentence, not just a number.** The `generic` updater — and this script — only rewrites the semver token on an annotated line; if the surrounding sentence's *meaning* changes (as `:147`'s did), no version tool fixes that. That's exactly why `:147` is reworded out of the propagation set instead of kept annotated.
- **`metadata.version` semantics** (§5 Q2): defaulted to tracking the package version. If ruled independent later, it's a one-line removal from the script's table and the future `extra-files` config — but once release-please owns bumps, an independent `metadata.version` becomes the *only* manually-bumped field left in the repo, which is worth deciding deliberately rather than by default.
- **The 10th-site problem is inherited, not solved.** Both the script's tables and the future `extra-files` list are enumerated; a *new* hardcoded literal introduced in future code (the next `codex_app_server.py`) is invisible to both, the same limitation §4 already accepted for the enumerated-vs-scan choice. Unaffected by this design; a repo-wide scan remains available as later hardening.
- **Annotation string collision.** The literal token `x-release-please-version` now appears in `tests/cli/test_cli.py`, `check_clean_install.sh`, and `README.md`; that's the intended trigger for future release-please, but any *other* document that quotes one of those lines verbatim (this spec, if it's ever merged into README-rendered docs) should not itself land inside a future `extra-files` entry.

## 4. Recommendation

**Option E.** The owner explicitly rejected the manual-bump interim (Option D) in favor of full automation from one root location, shaped to hand off cleanly to release-please. Option E delivers that: `pyproject.toml` becomes the *only* hand-edited version site; every other site is machine-written using release-please's own addressing conventions (verified from source, not assumed), so P01-T20 later means adding one config file and deleting one ~90-line stdlib script — no target file is reformatted a second time.

`codex_app_server.py`'s fix and `README.md:147`'s rewording are common groundwork and should happen regardless.
