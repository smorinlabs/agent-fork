# Session fork-command implementation plan

**Status:** implemented and locally verified 2026-08-14; authenticated post-implementation host acceptance remains separately gated

## Outcome

Add one read-only command-construction result to ordinary session inspection and
expose it through two exact companion-skill forms:

- `/agent-fork --session` and `$agent-fork --session` inspect the current agent
  session and include its native fork command.
- `/agent-fork --session-only` and `$agent-fork --session-only` print only that
  command.

Both forms call exactly `agent-fork session --json` from the active session
directory. The CLI infers that resolved directory and ambient Claude Code or
Codex identity. Neither form creates a branch or worktree, copies files, writes
registry or lineage state, touches the clipboard, or executes the returned
command.

## Locked command forms

For Claude Code, generate a fresh child UUID once per inspection and emit:

```text
cd <shell-quoted-resolved-directory> && claude --session-id <shell-quoted-fresh-child-uuid> --resume <shell-quoted-current-session-id> --fork-session
```

For Codex, emit:

```text
codex fork <shell-quoted-current-thread-id> -C <shell-quoted-resolved-directory>
```

The session command is a distinct template from REQ-28. It has no fork name,
Claude `-n`, configured agent extra arguments, preflight, or Codex rollout
check. `available` means the command is constructible from exactly one ambient
identity; it is not a claim that the installed native CLI can execute it. A
Claude child UUID is single-use and is regenerated by the next inspection.

`shlex.quote` output is normative. Shell-safe values may therefore appear
without visible quotes even though all interpolated values cross the same
quoting boundary.

## Result contract

Ordinary session JSON adds this open-schema object:

```json
{"fork_command":{"status":"available","command":"<exact command>"}}
```

The status and command invariant is:

| Ambient identity | `status` | `command` |
|---|---|---|
| Exactly one safe Claude or Codex identity | `available` | exact non-empty string |
| No identity | `not_detected` | `null` |
| Both identities | `ambiguous` | `null` |
| Identity or directory contains terminal-unsafe controls | `unsafe_input` | `null` |

Terminal-unsafe means C0 or C1 controls, DEL, or Unicode bidirectional control
characters. Shell quoting does not neutralize terminal controls, so unsafe
input is not printed as a command. Safe commands remain character-for-character
identical in JSON, human CLI output, and both skill routes.

Command status is independent of lineage status. Missing native binaries,
Codex app-server failure, missing parent evidence, stale inference, and missing
names do not change a safely constructible command from `available`.

`SessionInspection` owns one frozen `SessionForkCommand`. Repeated serialization
of the same inspection is byte-stable; separate detected Claude inspections
receive distinct UUIDv4 child IDs. `session validate` embeds that already-built
inspection document and does not regenerate the UUID.

## Adversarial review resolution

Codex returned `OBJECT` with eight findings. Claude Code returned `CONCUR WITH
AMENDMENTS` with ten findings. The reconciled amendments are:

1. Reject terminal-unsafe command inputs as `unsafe_input`; never emit raw
   control bytes and never rewrite a supposedly paste-exact command.
2. Add session help examples and define `available` as constructible, not
   preflighted. Scope REQ-29's no-known-bad-command rule to the mutating `fork`
   pipeline.
3. Use one private native renderer for REQ-28 and this template so quoting and
   agent syntax cannot drift.
4. Make both skill routes validate the same `fork_command` object. Full
   `--session` includes the exact command; `--session-only` emits only it.
5. Replace the substring-sensitive skill gate with an explicit exact-token
   allowlist. Mixed, misspelled, or option-like forms refuse before any CLI
   call.
6. Allocate `T-EMT-08..10` and `T-SES-28..32` before their tests, keep static
   skill checks unmarked, and move affected groups through `tdd` to `done`.
7. Keep T-SES-13's existing byte-identity contract. Its no-agent fixture does
   not generate a UUID; detected-agent determinism receives separate coverage.
8. Update the consolidated surface, D/REQ ranges, P01 references/tasks,
   companion metadata test, README, implementation prompt, and conformance
   trace without editing completed historical plans.
